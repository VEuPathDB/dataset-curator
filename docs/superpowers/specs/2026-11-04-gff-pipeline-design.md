# GFF pipeline

## Problem

An annotated genome loads through `fasta_*` and `NoPreprocess_*_genome_features`
classes. Their delivery is a FASTA and a GFF per sequence partition that ISF
(`InsertSequenceFeatures`) accepts. NCBI's GFFs do not load as published:

- GenBank GFFs model gene → CDS with no mRNA; ISF drops every such gene silently.
- Transcripts lack exons; split genes appear as repeated gene lines.
- Parentless RNAs vanish.
- Attribute keys the ISF map does not list are fatal, but only when ISF reaches
  the feature, minutes into a run.
- BioPerl 1.7.x reads ISF's GFF3 as GFF2, so every GFF must first pass through
  ApiCommonData's `preprocessGFF3`.

This spec is sub-project D of genome preprocessing: NCBI accession in,
partitioned ISF-ready files and a record of every change out. Background, and
the failures listed above: `docs/superpowers/research/2026-11-04-trial-isf-spike.md`
and `docs/superpowers/research/2026-11-03-genome-dataset-class-formats.md`
(on `design/dataset-entries` until it merges).

## Decisions

- Inputs come from NCBI only (GenBank or RefSeq annotation GFF, genomic FASTA,
  assembly report). Partition discovery sits behind one module so a hand-written
  `partitions.tsv` can serve other sources later.
- Detect, then declare: `survey` suggests transforms; only the curator's
  `recipe.json` runs. The recipe is the record.
- Default IDs are locus-tag based; `ids.tsv` overrides any input ID. Collisions are
  errors, never auto-suffixed.
- `preprocessGFF3` runs from the ApiCommonData checkout with host `perl`. It
  needs only core modules once its unused `use Bio::SeqIO` is removed (a
  separate ApiCommonData change).
- D knows nothing of proposals, dataset classes or entries. Its hand-off is a
  neutral partition list; mapping partitions to entries is sub-project F.

## Architecture

Four commands over one in-memory feature graph. Each command reads files and
writes files; nothing is held between runs, and each checks its predecessor's
outputs and checksums before running.

```
fetch <accession>  →  survey  →  (curator writes recipe.json)  →  build  →  finalize
```

Code lives in `shared/scripts/genome/`:

| Module | Job |
|---|---|
| `gff.js` | Parse GFF3 into a graph (sequences, features, parent/child edges) and serialize it. No line-level GFF logic elsewhere. IDs and `Parent`s stay raw (as written) in the graph |
| `feature-types.js` | Gene, transcript and protein levels |
| `fasta.js` | Stream FASTA; split and rename by sequence ID |
| `assembly-report.js` | Parse the NCBI assembly report; classify each sequence by rank |
| `partitions.js` | Ranking rule plus `partitions.tsv` overrides → partition plan |
| `ids.js` | ID policies (`ncbiDefault`, `none`) and `ids.tsv` |
| `transforms/*.js` | One pure function per transform, `(graph, args) → { graph, changes }`, and a registry carrying each transform's kind (`structural` or `attributes`), canonical order and the error codes that need a hand fix to the input GFF |
| `isf-map.js` | Read the ISF map XML; port of ISF's tree reshaping and type renames |
| `checks.js` | The checks `survey` and `build` share, and the finding constructor |
| `plan-build.js` | The build phases (IDs, transforms, partition, checks) as one pure function; `survey` previews with it and `build` runs it |
| `preprocess-gff3.js` | `perl -c` precheck and running ApiCommonData's `preprocessGFF3`; the checkout's commit and dirty flag |
| `record.js` | The `build.json` / `genome-build.json` contract: schema version, generator, file names |
| `workdir.js` | Work-area paths, `PipelineError`, sha256, atomic writes, staged directory swaps |
| `commands/*.js` | `fetch`, `survey`, `build`, `finalize` |
| `genome-pipeline.js` | The CLI |

## Work area

Given as `--workDir`, the validation workspace the data loader names.
`--apiCommonData` is the ApiCommonData checkout.

```
<workDir>/
  fetch/              raw NCBI files; fetch.json (url, time, sha256 per file)
  survey.json         findings, suggested recipe, partition counts
  recipe.json         curator-declared (see below)
  ids.default.tsv     generated by the ncbiDefault ID policy
  ids.tsv             optional, curator
  partitions.tsv      optional, curator
  build/              build.json; normalized.gff3; per partition genome.gff3, genome.fasta,
                      chromosomeMap.txt (chromosome primary only); all checksummed in build.json
  final/<partition>/  the files build.json's partitions[].final lists
  genome-build.json   the record, written last
```

`build` and `finalize` write into `build.tmp/` and `final.tmp/` and swap them in
only on success, so a refused or failed run leaves the previous output; a swap
interrupted by a crash is recovered on the next run. Every successful `build`
removes `genome-build.json`: `final/` without it is not finalized.

`recipe.json`:

```json
{
  "idPolicy": "ncbiDefault",
  "transforms": [
    { "name": "addMrnaToGeneCds" },
    { "name": "addExonPerCds" },
    { "name": "stripAttributes", "args": { "type": "gap", "keys": ["gbkey"] } }
  ],
  "ids": "ids.tsv",
  "partitions": "partitions.tsv"
}
```

`ids` and `partitions` are optional. Transforms run in the registry's canonical
order (`collapseSplitGenes`, `addMrnaToGeneCds`, `parentOrphanRnas`,
`addExonPerCds`, `stripAttributes`); the recipe chooses which run.

## The `genome-build.json` contract

`genome-build.json` is the hand-off to F. It is `build/build.json` plus the
fields `finalize` adds; consumers read it and never derive file names or counts
themselves.

| Field | Meaning |
|---|---|
| `schemaVersion` | `1`. A consumer refuses a version it does not know |
| `generator` | `{ name: "dataset-curator genome-pipeline", version }` (package version) |
| `source` | `"ncbi"` |
| `accession` | The assembly accession |
| `inputs` | Per role (`gff`, `fasta`, `report`): file name and sha256 |
| `recipe`, `ids`, `partitionsTsv` | sha256 of `recipe.json`; `{ file, sha256, applied }` for `ids.tsv` and `{ file, sha256 }` for `partitions.tsv`, or `null` |
| `idPolicy` | `{ name, renamed }` |
| `transforms[]` | `{ name, args?, changes, sample }` (up to 20 IDs), in run order |
| `normalized` | `{ path: "build/normalized.gff3", sha256 }` |
| `findings[]`, `warnings[]` | The non-error findings of the final checks |
| `partitions[]` | See below |
| `apiCommonData` | `{ commit, dirty, isfMap: { path, sha256 }, preprocessGFF3: { sha256, override } }`. `isfMap` is the map build checked against; `commit` and `dirty` are the checkout `finalize` ran from; `override` is true when `--preprocessGFF3` replaced the checkout's script |
| `builtAt`, `finalizedAt` | ISO timestamps |

Each `partitions[]` entry:

```json
{ "role": "primary", "soTerm": "chromosome", "organelle": null, "sequenceCount": 11,
  "dir": "final/primary_chromosome", "featureCount": 5120, "gffLines": 18734,
  "final": { "gff": "genome.gff", "fasta": "genome.fasta", "chromosomeMap": "chromosomeMap.txt" },
  "buildFiles": { "gff3": "<sha256>", "fasta": "<sha256>", "chromosomeMap": "<sha256>" } }
```

`role` is `primary`, `secondary` or `organelle`. `dir` is `final/<role>_<soTerm>`
for primary and secondary partitions and `final/organelle_<organelle>` for
organelles. `featureCount` is the number of gene trees ISF builds from the
partition's own GFF; 0 means ISF loads nothing from it, and then `final.gff` is `null`
(no `genome.gff` is written). `gffLines` is the raw feature-line count.
`final` lists the files in `dir`, relative to it; `chromosomeMap` is non-null for
a chromosome primary only. `buildFiles` are the sha256s of the `build/` files
`finalize` consumed; `final/` itself has no checksums (see finalize).

## Commands

### fetch

`fetch <assemblyAccession>` downloads the annotation GFF, genomic FASTA and
assembly report from NCBI FTP into `fetch/`. A re-run reuses local files; a
remote file whose sha256 differs from `fetch.json` is an error naming the file.
An assembly with no annotation GFF is an error.

### survey

Parses the inputs, runs every check (below) on the raw graph, and writes
`survey.json`: findings and a suggested `recipe.json`. It then previews the
suggested build in memory (ID policy, `ids.tsv` if present, suggested transforms)
and runs the checks again; those findings carry `stage: "suggested"`, raw ones
`stage: "raw"`. Suggested `stripAttributes` entries come from the preview,
because ISF drops some features (a CDS-only gene) before it checks their
attributes; so the suggested-stage findings still list the attribute errors the
suggested `stripAttributes` removes. A collision, an `ids.tsv` error or a
transform error needing a hand fix is reported as a finding and the preview
stops; `survey.json` is still written. Never modifies inputs.

### build

Runs four phases in fixed order; the recipe only chooses what happens in phase 2.

1. **IDs.** The ID policy, then the curator overrides from `ids.tsv`, then the
   collision check. `ncbiDefault`: gene = `locus_tag`, else the gene `ID`
   without its `gene-` prefix; an mRNA = its `ID` without the `rna-` prefix;
   any other transcript keeps its NCBI `ID`; protein = the CDS's `protein_id`;
   every `Parent` follows. Writes `ids.default.tsv`. `none` leaves IDs as they
   are. Two features resolving to one ID is an error naming both and the
   `ids.tsv` line that would fix it.
2. **Transforms**, in canonical order.
3. **Partition**, after all renames.

Then it re-runs the checks on the result and refuses to write `build/` while any
`error` remains. `ids.default.tsv` is written after phase 1 even when a later
phase refuses. Before anything, `build` checks that the fetched inputs match
`survey.json`'s; it records the sha256s of the recipe, `ids.tsv` and
`partitions.tsv` from the text it parsed, and the ISF map's sha256.

### finalize

First it refuses a stale build ("run build again"): a `build.json` of another
`schemaVersion`; `normalized.gff3` or any `buildFiles` entry changed or missing;
`recipe.json`, `ids.tsv` or `partitions.tsv` changed, added or removed since
build; or an ISF map at `--apiCommonData` that differs from the one build
checked against.

Then it runs `preprocessGFF3` on each partition's GFF into
`final/<partition>/genome.gff` (skipped when `featureCount` is 0), copies the
FASTA and `chromosomeMap.txt`, checks every file `final` lists exists and is
non-empty, and writes `genome-build.json`. Before the first run it checks the
script with `perl -c`; a failure names the `use Bio::SeqIO` fix. Until that
ApiCommonData change lands, `--preprocessGFF3` runs a copy without it; the
record notes the override.

`preprocessGFF3` emits PMID `Dbxref`s in Perl hash order, so its output is not
byte-stable. Checksums are taken on `build/`, not on `final/`.

## Transforms

| Name | Does | IDs it creates |
|---|---|---|
| `addMrnaToGeneCds` | A gene with CDS children and no RNA gets an mRNA; the CDSs move under it | `<geneId>_mRNA` |
| `addExonPerCds` | A transcript with CDSs and no exons gets one exon per CDS segment | `<transcriptId>_exon<n>`, numbered 5′→3′ |
| `collapseSplitGenes` | Repeated gene lines with one ID become one gene spanning min start to max end. Different sequences or strands are an error | — |
| `parentOrphanRnas` | A parentless RNA gets a coordinate ID and a new parent gene. Parentless RNAs on one sequence, span and strand share one gene; the same span on opposite strands is an error to fix in the input GFF | `rna_<seqId>_<start>_<end>_<type>`, `gene_<seqId>_<start>_<end>` |
| `stripAttributes` | Removes `keys` from features of `type` | — |

Created IDs come from the IDs phase 1 settled, so they are stable across runs.
Synthesized IDs use `_` only, never `:` or `-`. A created ID that already
exists is an error; the fix is an `ids.tsv` line renaming its source, not a
suffix.

A transform that changes nothing is a warning: the recipe declared something not
needed.

## IDs

`ids.tsv`, tab-separated, header `level old new`; `level` is `sequence`, `gene`,
`transcript` or `protein`. `old` is an input ID as NCBI wrote it (the `old`
column of `ids.default.tsv`). Applied in phase 1, after the ID policy and before
the collision check; IDs the transforms create follow from the settled IDs, so
they are changed by renaming their source. A `sequence` rename also renames
FASTA headers and assembly report rows.

Errors: an `old` not present; a repeated `old`; a `new` that clashes within its
level. A created-ID collision names the input ID whose `ids.tsv` line would
fix it.

## Partitions

Each nuclear top-level sequence gets a rank:

| Report | Rank |
|---|---|
| `assembled-molecule`, location type `Chromosome` | chromosome |
| other role, GenBank accession matches the WGS contig pattern (4–6 letters, 8+ digits) | contig |
| other role, any other accession | supercontig |
| location type is an organelle (`Mitochondrion`, `Apicoplast`, …) | organelle, by its location |

The highest rank present is the primary partition. Each lower rank present is a
secondary partition. Each organelle is its own partition. A missing accession,
an unknown role or location type, or a sequence absent from the report is a
survey error. `partitions.tsv` (header `sequence role soTerm organelle`)
overrides any sequence.

`chromosomeMap.txt` for a chromosome primary: `sequenceId \t Sequence-Name \t order`,
in report order.

## Checks

Shared by `survey` (on the raw graph) and `build` (on its output). Each finding
has a severity (`error`, `warning`, `info`), a count, up to 20 sample IDs, and a
suggested fix: a transform, a `stripAttributes` entry, or an `ids.tsv` or
`partitions.tsv` line.

| Group | Check | Severity |
|---|---|---|
| Structure | gene → CDS with no RNA | error |
| | transcript with CDS and no exons | error |
| | repeated gene lines with one ID | error |
| | parentless RNA | error |
| | gene with no children | warning |
| | feature type the ISF map does not handle | warning |
| | CDS whose parent is a gene (the gene also has an RNA child) | error |
| | gene or RNA with no ID | error |
| | gene, transcript and exons not on one strand | error |
| | a transcript's CDS segments not contained in its exons | error |
| Attributes | key not among the map's qualifiers for the feature's ISF type | error |
| IDs | duplicate ID | error |
| | `:` or `-` in a synthesized ID | error |
| | transcript whose CDSs carry more than one distinct `protein_id` | error |
| Sequences | GFF seqId missing from the FASTA | error |
| | FASTA or GFF sequence missing from the report | error |
| | unknown role or location type, ambiguous accession | error |
| | partition counts by rank | info |

Attribute checks need ISF's types, not the GFF's. `isf-map.js` reads the map
(`lib/xml/isf/genemRNAExonCDS2Gus.xml` in `--apiCommonData`) and ports the type
renames of the preprocessor it names,
`ApiCommonData::Load::genemRNAExonCDS2BioperlTree` (gene with an mRNA becomes
`coding_gene`, and so on). The check allows the `Dbxref` and
`previous_systematic_id` keys `preprocessGFF3` adds. The port is the one place D
copies production logic; it is tested against the Perl module's behaviour on the
golden genome.

## Errors

Every failure is a `PipelineError` naming the command, the file, and the next
step: the transform or override that fixes it, the drifted fetch file, the
missing `--apiCommonData` path, the stale input, or the `preprocessGFF3` compile
failure. Input that cannot be read (a malformed GFF, a duplicate FASTA ID, a
hand-edited record) is reported before anything is staged. Only I/O errors are
wrapped generically; anything else is a bug and propagates.

## Testing

- `gff.js`: parse → serialize is byte-identical for NCBI escaping, multi-value
  attributes and comment lines.
- Each transform: a fixture graph, expected graph and `changes`; the zero-change
  warning; created-ID collision.
- `ncbiDefault` and `ids.tsv`: renames propagate to `Parent`, FASTA and report;
  each `ids.tsv` error.
- Partitions: report fixtures for chromosome primary with supercontig and contig
  secondaries, supercontig primary with contig secondary, contig-only, organelles,
  overrides, each report error.
- Each check, from a fixture that triggers it.
- `fetch` against a stubbed HTTP layer: reuse, drift error, no annotation GFF.
  No network in tests.
- Golden: a cut-down E. cuniculi GB-M1 (GCA_000091225) set, two chromosomes,
  including ECU10_0805 (split gene), ECU11_0375 (a protein-coding gene and a
  tRNA gene sharing one locus tag) and a parentless RNA, with an `ids.tsv`, through `fetch` (stubbed), `survey`, `build` and `finalize`
  on a fixed clock. Compared with checked-in `survey.json` and `genome-build.json`
  (checkout commit, dirty flag, ISF map and script sha256 and generator version
  masked). The final GFF is not checked in: it is pinned as its line count,
  per-type counts and a sha256 taken after sorting each line's `Dbxref`s.
  Skipped with a message when `APICOMMONDATA_DIR` or `perl` is unavailable.
- Type-rename port: on the golden genome, ISF types from `isf-map.js` match
  those in the spike's `bioperltree.out`, cut to the same two chromosomes and
  checked in as a fixture.

## Scope

In scope: the four commands, the modules above, the transforms listed, ID
policy and overrides, partitions, checks, `genome-build.json`.

Out of scope: dataset entries and `organism.json` constants (F); the trial ISF
runner and the post-load protein-count check (C); functional files (E);
non-NCBI sources and `.gbff`; removing `use Bio::SeqIO` from ApiCommonData's
`preprocessGFF3` (a separate ApiCommonData change); any transform beyond those
listed.
